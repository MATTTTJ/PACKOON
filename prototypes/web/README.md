# 너구리 보부상 웹 프로토타입

브라우저에서 바로 열리는 프로토타입. **실제 게임 코드가 아니라 기획 검증용**이다. 콘텐츠와 게임 루프는 이 웹 버전으로 정하고, 많은 부분이 정해지면 Godot 4로 옮긴다. 옮길 때는 동작과 수치만 참고하고 코드는 새로 짠다.

- 플레이: https://mattttj.github.io/PACKOON/ (이 폴더로 넘어온다)
- 내 컴퓨터에서: `index.html`을 더블클릭해 브라우저로 연다. 빌드나 서버가 필요 없다.
- 저장: 화면 위 "저장" 버튼이나 너구리의 책 아래 "저장하기". 플레이 중 30초마다, 다음 지역으로 넘어갈 때도 저절로 저장된다 (대화·전투·미니게임 중에는 저장하지 않음). 저장은 그 기기의 브라우저에만 남는다. 시작 화면의 "이어서 하기"로 다시 시작하고, 책 아래 "처음부터 하기"는 한 번 더 눌러야 저장을 지운다 (`js/engine/save.js`).
- 지역 고르기: 시작 화면 아래 **개발용 · 이 지역부터 시작** 버튼을 누른다. 또는 주소 뒤에 `?region=<지역 id>`를 붙이면 그 지역부터 시작한다 (예: `index.html?region=dolneomeo`). 앞 지역은 그 지역의 `finish`대로 마친 것으로 친다. 확인용 바로가기라서 앞 지역의 단서 내용은 비어 있다.

지금 들어 있는 지역: 1 단풍골 → 2 돌너머 마을 → 3 큰 장터 → 4 북쪽 영산(엔딩). 처음부터 엔딩까지 이어서 플레이할 수 있다. 한 지역이 끝나면 끝 화면의 버튼으로 다음 지역에 들어가고, 보따리·연장·책(일기·단서·장부)·아빠의 수첩·호감·깨어난 가보는 그대로 이어진다. 체력은 다시 찬다.

## 첫 화면 (타이틀 장면)

처음 들어오면 가을 숲 타이틀 장면이 뜬다. 메뉴는 **이어서 하기**(저장이 있을 때) · **새로 시작**(지금의 프롤로그 화면으로) · **움직임 켜기**다. 주소에 `?region=`이 있으면 건너뛴다.

- 원본은 팀이 따로 만든 packoon-layer-studio (스튜디오 편집기). 장면 코드(`src/studio-fragment.html`)를 `js/title/title-scene.js`로, 그림 `assets/*.png` 12장을 `assets/title/`로 그대로 옮겼다. 편집기 패널·슬라이더·저장 상태 복원만 뺐다.
- 설정은 스튜디오의 `scene-defaults.json` 값 그대로다 (`assets/title/scene-defaults.json`, 코드용 사본은 `js/title/scene-data.js`). 전체 입체감 15%, 안개 43 px/s, 팩쿤 반응 0.25, 숲길 반응 0.2, 까치 숨김.
- **자동 재생 없음**: 움직임 중 눈의 불편함 보고가 있어, 열 때마다 정지 상태다. 움직임 켜기를 직접 눌러야만 움직인다. 기기의 "동작 줄이기"가 켜져 있으면 알리고, 움직이는 중에 켜지면 멈춘다. 이것으로 불편함이 해결됐다고 보지는 않는다.
- 이미지 보간(`imageSmoothingQuality=high`)과 흐림 캐시는 원본 그대로다. 정지 화면은 스튜디오와 픽셀 단위로 같다 (1280×720, 시간 0, 마우스 가운데에서 비교).
- 첫 화면을 닫으면 프레임 루프·ResizeObserver·마우스 이벤트를 정리하고 큰 그림도 메모리에서 놓는다.
- 그림 12장이 원본 PNG라 합쳐 약 16MB다. 처음 열 때 불러오는 동안 "가을 숲을 불러오고 있습니다"가 뜨고, 그동안에도 메뉴는 누를 수 있다.
- 스튜디오에서 설정을 바꾸면 `scene-defaults.json`을 `assets/title/`에 다시 복사하고 `js/title/scene-data.js`의 같은 값을 맞춘다. 그림을 바꾸면 `assets/title/`의 PNG를 바꾼다.

## 표(CSV)와 게임 데이터

아이템(이름·레어도·설명), 보스 부위(이름·내구도·부수면 얻는 것·핵심), 달래기 진정수치, 가보 가공법, 아빠의 수첩 메모, 미니게임·채집 수치(`minigames.csv`), 조작감·시간 수치(`tuning.csv`)는 **`design/data/*.csv`가 유일한 원본**이다. 게임은 표에서 만든 `js/data/tables.js`를 읽는다 (더블클릭으로 열 때 브라우저가 CSV를 못 읽게 막아서, 표를 데이터 파일로 바꿔 둔다).

- 표(`minigames.csv`·`tuning.csv` 포함)를 고친 뒤: `node prototypes/web/tools/build-data.js` (레포 맨 위 폴더에서). 외부 패키지 없이 node만 있으면 된다.
- 맞는지만 보기: `node prototypes/web/tools/build-data.js --check` (표와 다르면 실패한다)
- 가공법·진정수치 칸의 물건 이름이 items.csv에 없거나 모양이 틀리면 변환기가 어느 줄인지 알려 주고 멈춘다. 미니게임·조작·시간 표도 필수 값 누락·빈 칸·숫자 오류·판정 범위를 검사한다.
- `tables.js`는 직접 고치지 않는다.
- 코드에 남는 것: 대사, 위치, 그림, 진행 순서, 공격 종류와 예고 글, NPC·지역 이름(대사에도 적혀 있어서), 먹으면 오르는 체력 같은 게임 전용 값. 수치 단위와 표 편집 방법은 `design/data/README.md`를 따른다.

## 새 버전을 올릴 때

`index.html`이 부르는 css·js 주소 끝에 `?v=20261029b` 같은 버전 표시가 붙어 있다. 파일을 고쳐 올릴 때마다 이 값을 **모두 같은 새 값**으로 바꾼다 (날짜 + 알파벳 하나면 충분하다). 안 바꾸면 GitHub Pages가 파일을 10분쯤 브라우저에 저장해 두는 탓에, 새 `index.html`과 옛 js가 섞여 검은 화면이 뜰 수 있다.

## 검증하려던 것 (단풍골)

- 물물교환만으로 지역 하나의 흐름이 돌아가는가 (교환 연쇄 2단계, 호감 축 3종)
- 타이밍 채집이 단순 줍기보다 재미있는가
- 부위 공략 전투(부위 공격 → 회피 → 빈틈 표식 타격 → 내구도 깎기)가 턴제보다 템포가 좋은가
- 필드(도트)와 전투(수묵화)의 스타일 전환이 효과적인가
- NPC 전투(꿀밤으로 연장을 뺏기고 피하기만)가 재미 요소가 되는가

## 검증하려던 것 (돌너머 마을, 제안)

- 같은 물건(칡꽃)이 지역에 따라 귀해지는 교환이 재미있는가
- 교환 연쇄 3단계(칡꽃 → 결명자 → 맷돌 깨어남 → 메밀가루 → 길)가 막히지 않고 이어지는가
- 가보를 직접 깨우고 그 가보로 약을 만드는 흐름이 단풍골(남이 약을 지어 줌)과 다르게 느껴지는가
- 졸음 깨우기, 돌 쌓기 같은 짧은 미니게임이 대화 사이에 잘 섞이는가
- 아빠의 소원 돌로 보스를 달래는 장면이 부수는 것보다 끌리는가

## 검증하려던 것 (큰 장터, 제안)

- 앞 지역의 가보(맷돌)가 다음 가보(시루)를 깨우는 흐름이 자연스러운가
- 낮과 밤을 숙소에서 바꾸는 것이 장터 분위기와 부엉 영감 성격을 잘 살리는가
- 아빠의 엿을 도깨비에게 줄지 고르는 선택이 마음에 남는가
- 엿가위 장단, 김 올리기 같은 리듬·조절 미니게임이 대화 사이에 잘 섞이는가

## 검증하려던 것 (북쪽 영산과 엔딩, 제안)

- 숨은 사연이 퍼즐이 아니라 장부 한 장과 산군의 이야기를 "받는" 장면으로 잘 전해지는가
- 마지막 교환(이름을 내놓기)과 새 이름 짓기가 물물교환 세계의 결말로 납득되는가
- 설피·지름길처럼 "속도가 아니라 접근"으로 길이 열리는 성장이 재미있는가
- 겨울에서 봄으로 바뀌는 전환이 보상으로 느껴지는가

일반 `<script>`를 차례로 읽는 방식이라 `file://`로 열어도 돈다(ES 모듈은 `file://`에서 막힌다). 엔진 파일의 맨 위 이름은 파일끼리 공유된다. 지역 파일은 `(()=>{ ... })()` 안에 넣고 `define*` 함수로만 내보내서, 지역끼리 이름이 부딪히지 않게 한다.

id는 `design/data/*.csv`와 같다. 지역 id는 `regions.csv`, 아이템은 `items.csv`, NPC는 `npcs.csv`, 전투 상대는 `bosses.csv`, 부위는 `boss_parts.csv`의 id를 쓴다.

## 지역 하나 더하기

1. `js/regions/<지역 id>/` 폴더를 만들고 단풍골 폴더를 본보기로 파일을 나눈다.
   - `region.js`: `defineRegion(id, {...})`로 지역 정보와 처음 상태, `defineIcons`(아이콘) / `defineGather`(채집)
   - `art.js`: NPC 도트 그림과 소품
   - `field.js`: 배경, 장애물, 날씨, 휘두르기·쓰러짐 처리
   - `enemies.js`: `defineEnemies`로 전투 상대와 수묵 그림
   - `story.js`: NPC 대화와 교환, 지금 할 일, 지역 전용 미니게임
2. `index.html`의 지역 `<script>` 목록 아래에 새 파일을 같은 모양으로 덧붙인다 (`game.js`보다 위).
3. 앞 지역의 `defineRegion`에 `next: '<새 지역 id>'`를 적는다.

가보는 `awaken('<가보 id>')`로 깨운다. 깨어난 가보는 `G.awake`에 남고, 가공법은 깨어난 뒤에만 쓰인다. 지역 전용 미니게임 창은 돌너머의 돌 쌓기처럼 지역 파일에서 만들어 `#shell`에 붙이고 `defineMinigame`으로 등록한다.

엔진 파일은 고치지 않아도 된다. 엔진에 없는 기능(새 공격, 새 미니게임)도 지역 파일에서 `defineAttacks` / `defineBullets` / `defineMinigame`으로 더할 수 있다. 여러 지역이 같이 쓸 것 같으면 그때 엔진으로 옮긴다.

### 구역·경치·길손·도장 쓰는 법

```js
}
```

- 구역의 `w`는 화면 폭 400 이상이다. `ground`는 발이 닿는 바닥 y이며 기본은 192다. 발판·NPC·조사점은 구역 안 좌표다. NPC·길손·조사점의 `y`를 생략하면 바닥이다. `npcs`를 생략하면 NPC의 `zone`으로 거르고, NPC의 `zone`도 없으면 시작 구역에 둔다. `npcs:[]`는 아무 NPC도 두지 않는다.
- `drawBack`, `drawScenery`, `drawActors`, `drawFront`, `weather`, `weatherFront`, `ambient`, `step`, `onHit`, `onPickup`, `drawPickup`, `drawDig`, `maxX`, `faint`, `fieldBoss`는 현재 구역 것만 부른다. 구역 방식에서는 지역의 같은 이름 함수로 자동 대체하지 않는다. 필요한 공통 그림 함수는 각 구역에서 참조한다. `goal`, `onStart`, 교환·전투 결과 함수는 계속 지역에 둔다. 전투를 여는 조건도 해당 구역의 `step`에 둔다.
- 구역별 가변 상태는 `newState()`가 돌려주며 `zoneState()`로 읽는다. 이 함수는 순수한 초기값만 만든다. `G.digs`·`G.pickups`는 기존 저장 구조를 유지하고 `zone`으로 거른다. 구역에 선언한 채집·줍기 지점은 한 번만 복제한다. `id`는 구역 왕복과 저장 뒤에도 유지한다. 기존 `newState()`가 만든 지점이나 이후 코드에서 추가하는 지점은 `zone`이 없으면 시작 구역 소속이다. 다른 구역에 추가할 때는 `zone`도 적는다. 적의 상태·그림·갱신은 해당 구역에 함께 둔다.
- 가장자리 출구는 문자열 또는 `{to,need,reason,drawBlocked,toX,toY}`다. x가 16 미만 또는 `w-16` 초과가 되도록 밖으로 걸으면 전환하고, 기본 도착점은 반대쪽 가장자리다. 문은 E 또는 휴대폰 말걸기 버튼으로 연다. 문 도착점은 `toX`·`toY`, 없으면 대상 구역의 시작점이다. 조건은 통과 직전에 다시 검사한다. `need`는 소비 없는 판정 함수이며 `reason`은 막힌 이유다. `drawBlocked(x,y)`에는 화면 좌표를 준다. 이동·공격 입력은 전환 때 비운다.
- 조사·문·경치·길손·도장은 가까운 하나가 선택된다. 가로 차이는 기존 말 걸기 거리(현재 30px) 미만, 세로 차이는 `field_interact_y`(현재 24px) 미만이다. 경계와 같은 값은 제외한다. 조사 `text`는 문자열 또는 문자열 배열이며 한 번 열 때 한 칸씩 진행해 마지막에 머문다. 1~2줄은 문자열 안 줄바꿈으로 적는다.
- 길손은 `REG.wanderers`에 `{id,zone,x,draw,talk}`로 두어도 된다. 기존 `talk()`·선택지·교환 함수를 그대로 쓴다. **사연이나 교환이 끝난 콜백에서** `finishWanderer(id)`를 부른다. 거절·취소만으로 끝내지 않는다. 다시 말하면 `greeting`을 쓴다. 완료 id는 `G.f.wanderersDone`, 전체 수는 `G.f.wandererCount`에 저장된다. `wandererCount(regionId?)`로 지역별·전체 수를 읽는다. id는 한 지역 안에서 고유해야 한다.
- 도장은 기본적으로 E로 발견하고, `auto:true`이면 가까이 닿을 때 발견한다. 발견 전에는 `draw`를 호출하지 않아 숨긴다. 주변 단서는 지역 배경에 그린다. `note`는 `notebook.csv`의 `알게되는키`와 연결한다. 같은 형식의 행에 `종류=도장`, `쓴이=아빠`, `대상=쪽 제목`, `내용=그날 이야기`, `상태=제안`을 적고 데이터를 재생성한다. 기존 동물·물건 id를 바꾸지 않고 지역별 새 쪽id를 쓴다. 발견 때 `learn(note)`·반짝임·획득음은 한 번만 실행된다. 수첩의 도장 탭에서 읽는다. `stampCount(regionId?)`, `G.f.stampCount`, `G.f.stampsByRegion`으로 집계하며 `G.f.stampsFound`는 지역+id별 발견 기록이다. 열두 개 수집 뒤 엔딩 장면은 지역 콘텐츠 단계에서 연결한다.
- 경치는 HUD·패드·대화를 걷고 필드·채집·전투를 멈춘다. 처음에만 `thought`와 `diary`를 보인다. `from`·`to`는 카메라 x(px)이며 `0..w-400`으로 제한한다. `t=경과 프레임/vista_pan_frames`를 0~1로 제한하고 `from+(to-from)×(3t²-2t³)`으로 이동한다. 예: 0→400의 절반 시점은 200px다. 각 원경은 `cam=반올림(카메라 x×speed)`로 그리며 `draw(cam,t)`도 받는다. 멀수록 작은 `speed`를 쓴다. 그림 함수 배열도 허용하며 생략한 속도는 `(순번+1)/겹 수`다. R/M과 정수 좌표를 쓴다.
- 패닝은 현재 480프레임(8초) 뒤 멈춘다. 숨긴 탭에서는 경치 시간이 멈추고, 움직임 줄이기는 시작 위치의 정지 화면이다. 소리는 `wind` 또는 `water` 환경음 하나를 반복하며 돌아오면 정리한다. 다음 키·터치 한 번으로 돌아오고 그 입력은 필드에 전달하지 않는다. 경치·화면 전환 중에는 저장하지 않는다.
- 구역·위치·조사 횟수·길손·도장·첫 경치 기록은 기존 저장 키에 함께 남는다. 구역 정보 없는 옛 저장은 시작 구역에서 기존 위치와 진행을 이어받는다. 모르는 구역 id는 시작 구역의 시작점으로 돌린다. 구역을 선언하지 않은 지역과 `?classic=1`에서는 확장 상호작용을 쓰지 않는다. 새 `G.f` 칸이 없으면 아직 발견·완료하지 않은 상태로 읽는다.

수치 원본은 `tuning.csv`의 `field_interact_y`, `zone_transition_frames`, `vista_pan_frames`다. 판정은 60Hz 갱신 기준이며 전환은 현재 18프레임(0.3초), 움직임 줄이기에서는 즉시다. 구역마다 핸들러나 타이머를 등록하지 않고, 전환 때 Vfx 대기열과 필드 입자를 비운다.

### `defineRegion`에 채울 것

| 이름 | 뜻 |
|---|---|
| `order` | 지역 순서 (regions.csv의 순서). 주소에 지역이 없으면 가장 작은 것부터 |
| `next` | (선택) 다음 지역 id. 있으면 끝 화면에 다음 지역 버튼이 나온다 |
| `finish(g)` | (선택) 뒤 지역부터 바로 시작할 때 이 지역을 마친 상태로 만드는 함수 |
| `name` | 화면에 나오는 지역 이름 |
| `world`, `startX` | 필드 가로 길이, 주인공 시작 위치 |
| `platforms` | 올라설 수 있는 통나무 `[{x, y, w}]` |
| `clueTotal` | 이 지역의 아빠 단서 개수. 책과 끝 화면은 지나온 지역을 모두 더해 센다 (`clueTotalSoFar()`) |
| `cover` | 상단 꼬리표(`tag`)·부제(`sub`), 시작 전 할 일 글(`ready`), 앞 지역 끝 화면의 버튼 글(`go`), 시작 화면(`title`), 끝 화면(`end`) 글 |
| `newState()` | 처음 상태: `inv`(보따리에 더해짐), `pickups`(줍는 것 `{x, y, item}`), `digs`(흙더미 `{x, item}`), `f`(진행 표시, 앞 지역 것과 합쳐지니 이름이 겹치지 않게), `rel`(NPC id별 호감 축, 이미 만난 NPC는 앞 값을 이어 씀), 그 밖에 지역 전용 상태(새 지역 것으로 바뀜) |
| `onStart()`, `endStats()` | 시작할 때 할 일, 끝 화면의 숫자 `[[이름, 값]]` |
| `npcs` | `[{id, name, x, talk(), draw(x, y, 방향), props(npc)?}]` |
| `goal()` | 지금 할 일 글 |
| `maxX()` | 지금 갈 수 있는 오른쪽 끝 |
| `step()` | 매 프레임 지역 진행 (몹, 장애물, 전투 시작 조건 등) |
| `onHit(x1, x2, 피해, 방향)` | 휘두르기가 흙더미 말고 다른 것에 닿았을 때 |
| `faint()` | 체력이 다 떨어졌을 때 돌아갈 자리 |
| `drawBack()` | 하늘·배경·땅 |
| `drawPickup(a, x, 흔들림)` | 줍는 것 하나 그리기 |
| `onPickup(a)` | (선택) 무언가를 주웠을 때 |
| `drawDig(d, x)` | (선택) 채집 자리를 직접 그리고 `true`를 돌려준다 (없거나 `false`면 흙더미) |
| `drawScenery()`, `drawActors()`, `drawFront()`, `ambient()` | (선택) 큰 배경물, 장애물·몹, 맨 앞(날씨 등), 멈춘 동안에도 도는 날씨 움직임 |
| `fieldBoss()` | (선택) 필드 보스 체력 막대를 띄울 때 `{name, hp, max}` |
| `gatherDiary` | (선택) 처음 채집했을 때 일기 `[id, 글]` |
