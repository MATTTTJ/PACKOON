# 너구리 보부상 웹 프로토타입

브라우저에서 바로 열리는 프로토타입. **실제 게임 코드가 아니라 기획 검증용**이다. 콘텐츠와 게임 루프는 이 웹 버전으로 정하고, 많은 부분이 정해지면 Godot 4로 옮긴다. 옮길 때는 동작과 수치만 참고하고 코드는 새로 짠다.

- 플레이: https://mattttj.github.io/PACKOON/ (이 폴더로 넘어온다)
- 내 컴퓨터에서: `index.html`을 더블클릭해 브라우저로 연다. 빌드나 서버가 필요 없다.
- 저장: 화면 위 "저장" 버튼이나 너구리의 책 아래 "저장하기". 플레이 중 30초마다, 다음 지역으로 넘어갈 때도 저절로 저장된다 (대화·전투·미니게임 중에는 저장하지 않음). 저장은 그 기기의 브라우저에만 남는다. 시작 화면의 "이어서 하기"로 다시 시작하고, 책 아래 "처음부터 하기"는 한 번 더 눌러야 저장을 지운다 (`js/engine/save.js`).
- 지역 고르기: 시작 화면 아래 **개발용 · 이 지역부터 시작** 버튼을 누른다. 또는 주소 뒤에 `?region=<지역 id>`를 붙이면 그 지역부터 시작한다 (예: `index.html?region=dolneomeo`). 앞 지역은 그 지역의 `finish`대로 마친 것으로 친다. 확인용 바로가기라서 앞 지역의 단서 내용은 비어 있다.

지금 들어 있는 지역: 1 단풍골 → 2 돌너머 마을 → 3 큰 장터 → 4 북쪽 영산(엔딩). 처음부터 엔딩까지 이어서 플레이할 수 있다. 한 지역이 끝나면 끝 화면의 버튼으로 다음 지역에 들어가고, 보따리·연장·책(일기·단서·장부)·아빠의 수첩·호감·깨어난 가보는 그대로 이어진다. 체력은 다시 찬다.

확장판은 `M` 또는 지도 버튼으로 **길 지도**를 연다. 단풍골 늙은 까치의 보자기 장면을 마치면 열리며, 만나지 않았다면 돌너머 출발 때 열린다. 가 본 구역만 밝게 표시하고 선택할 수 있다. 방향키로 고른 뒤 Enter, 또는 구역을 누른 뒤 **까치 떼 부르기**로 이동한다. Esc·M·닫기 버튼으로 닫는다. 전투·대화·미니게임·경치·전환 중에는 열리지 않는다. `classic=1`에는 지도가 없다.

젊은 까치 여섯 마리 중 네 마리가 보자기 네 귀를 물고 아이를 옮긴다. 시간·착지 여백은 `tuning.csv`의 제안 값이며, 동작 줄이기에서는 바로 도착한다. 창을 벗어나거나 숨긴 동안에는 연출 시계를 멈춘다. 지역별 채집·바닥 물건·보스·구역 상태와 완료 여부를 보관하므로 돌아와도 이어진다. 떠날 때 남은 물건을 자동으로 줍지 않는다. 필수 약 배달·지역 종료·귀향 장면은 다시 시작하지 않으며, 엔딩 이름 입력을 마치면 지도 여행을 이어 갈 수 있다. 지역 보관이 없는 옛 저장은 현재 지역과 현재 구역만 방문한 상태로 연다.

지역을 끝내고 지도로 그 지역을 더 둘러봤더라도, 아직 다음 지역에 들어가지 않았다면 지도 아래에 기존 출발 버튼을 남긴다. 이 버튼은 원래 지역 종료 뒤의 출발이며, 안 가 본 구역을 까치로 고르는 기능과는 별개다. 엔딩 뒤에는 앞 세 지역에도 봄 색과 풀밭을 적용하고 낙엽·서리·눈을 멈춘다. 엔딩 전 그림과 classic 그림은 유지한다.

## 자동 검수

레포 맨 위에서 `node prototypes/web/tools/qa/run.js`를 실행한다. Node 24 이상과 Chrome이 필요하며, 패키지 설치나 게임 빌드는 없다. Chrome을 찾지 못하면 `CHROME_PATH`에 실행 파일 경로를 지정한다. PR과 main 푸시에서도 같은 명령을 실행한다. 실패가 하나라도 있으면 종료 코드 1, 경고만 있으면 0이다.

```text
node prototypes/web/tools/qa/run.js
node prototypes/web/tools/qa/run.js --quick
node prototypes/web/tools/qa/run.js --only dialogue
node prototypes/web/tools/qa/run.js --only play-expanded
node prototypes/web/tools/qa/run.js --only save,mobile
```

`--quick`은 브라우저를 열지 않는다. `--only` 이름은 `syntax`, `data`, `versions`, `csv`, `dialogue`, `play-expanded`, `play-classic`, `speakers`, `edges`, `save`, `mobile`, `map`, `drops-floor`, `drops-persistence`, `drops-departure`, `drops-full`이다. `static`과 `runtime`은 각각의 묶음이며 쉼표로 여러 검사를 고를 수 있다. `speakers`는 두 모드를, `edges`는 확장판 연속 플레이를 먼저 실행한다.

| 검사 | 확인하는 것 |
|---|---|
| 정적 | 저장소 JS의 `node --check`, `build-data.js --check`, index 자산의 `?v=` 일치, CSV UTF-8 BOM·id 중복 |
| 대사 | `talk`·이야기 배열의 상수 대사와 상수 분기. 너구리 외 화자의 조작어, 아이에게 하는 하게체, 타누키 표식, 두 줄 초과는 실패. 한 줄 40자 초과는 경고 |
| 연속 플레이 | 빈 저장에서 기본 확장판(사연 켬)과 `?classic=1`을 각각 실제 키·마우스로 진행. 목표·입력·소지품·지역별 결과와 막힌 지점을 기록 |
| 화자·이동 | 표시되는 대사마다 현재 구역의 NPC·길손·명시된 직접 그리기 인물을 대조. 가장자리를 넘을 때 유지한 방향키와 도착 뒤 이동을 기록 |
| 저장 | 실제로 물건을 주운 뒤 수동 저장, 같은 출처에서 새로고침·이어 하기 후 비교. 깨진 JSON으로 시작해 새 게임이 가능한지 확인 |
| 휴대폰 | 390×844 터치 에뮬레이션으로 첫 화면·출발 화면·대화·보따리·손일 창을 열어 44×44px 버튼과 요소 밖 글 넘침을 측정 |
| 지도 | 잠금·해금·방문한 구역 선택, 키보드·터치 이동, 연출 정지·동작 줄이기, 네 지역 왕복과 바닥 물건·보스·진행·저장 복원, 옛 저장·모드 왕복, 44×44px 표적 확인. 격리 상태를 만든 검사는 연속 플레이 기록과 구분 |

규칙과 허용 목록은 [`prototypes/web/tools/qa/rules.json`](tools/qa/rules.json)에 있다. 이 JSON의 `dialogue`에서 조작어·하게체 패턴·길이 기준을, `speakers`에서 화자 예외를 고친다. 어른끼리 대사는 `adultDialogueAllowlist`에 정확한 화자·대사·파일과 `reason`을 적는다. 직접 그리는 인물은 지역·구역·표시 조건까지 한정한다. 기록 화자도 필요한 경우 호출 스택으로 범위를 좁힌다. 실제 위반을 통과시키기 위한 넓은 예외는 넣지 않는다.

`qa-out/`은 git에서 제외한다. 매번 새 결과 폴더에 `report.json`, `report.md`, 입력 로그·화면·Chrome 로그와 격리 프로필이 생기며, 최근 요약은 `qa-out/latest.json`·`latest.md`다. 자체 정적 검출 대조군은 `node prototypes/web/tools/qa/self-test.js`로 실행한다. 임시 파일에 위반을 넣어 검출하고 복구·삭제하며 게임 파일은 건드리지 않는다.

브라우저 검사는 루프백 HTTP 서버와 결과 폴더 안의 새 Chrome 프로필을 쓴다. 사용자 브라우저 저장이나 기본 프로필은 쓰지 않는다. 이 HTTP 저장은 `file://` 실행 저장과 별개다. 화자 감시와 미니게임 관찰 코드는 시험 페이지에만 주입하며 진행값·위치·소지품은 직접 바꾸지 않는다. 연속 플레이의 긴 이동에서는 시험용 `requestAnimationFrame` 시계를 최대 6배로 돌리고, 근거리 이동·대화·미니게임은 정상 속도로 돌린다. 실제 플레이 시간이나 조작감 측정으로 쓰지 않는다. 같은 목표 240초 정체 기준은 `rules.json`의 `runtime.stallSeconds`에서 바꾼다. 전체 명령은 19분을 넘으면 실패하며 CI 제한은 20분이다. Chrome 시작 제한을 피하기 위한 `--no-sandbox`는 이 로컬 시험 프로세스에만 적용한다.

끝까지 진행했더라도 선택 대사 전체·초보자의 길 찾기·말투의 자연스러움·인과·소리·조작감까지 통과한 것은 아니다. 동적 대사 본문은 정적 검사로 모두 해석할 수 없고, 화자 검사는 실제로 표시한 줄만 확인한다. 선택한 검사에 필요한 지역·장면을 실행하지 못하면 실패 보고에 남긴다. 실제 옛 저장 호환과 휴대폰 실기기는 별도 검수가 필요하다. 항목별 구분은 [검수 점검표](../../design/checklists/review.md)를 따른다.

## 인물 사연과 저장 (PA-43)

확장판 새 게임은 [인물 사연](../../design/proposals/characters.md)을 기본으로 켠다. 비교하려면 `?arcs=0`으로 새 게임을 시작한다. `?classic=1`은 사연을 끈 옛 구성이며 `arcs=1`을 함께 붙여도 사연은 꺼진다.

새 게임에서 정한 참·거짓 값을 `G.f.arcs`에 저장하고 지역 이동과 이어서 하기에서 유지한다. 주소의 `arcs` 값을 바꿔도 이미 저장한 선택은 유지하며, classic으로 불러오면 사연을 끈다. 이 칸이 없는 옛 저장은 확장판에서 기본으로 켜고, `?arcs=0`이나 classic에서는 끈다. classic에서 저장한 `false`는 확장판으로 이어도 유지한다. 사연은 선택 장면이며 필수 진행을 막지 않는다.

## 첫 화면 (타이틀 장면)

처음 들어오면 가을 숲 타이틀 장면이 뜬다. 메뉴는 **이어서 하기**(저장이 있을 때) · **새로 시작**(지금의 프롤로그 화면으로) · **움직임 켜기**다. 주소에 `?region=`이 있으면 건너뛴다.

- 원본은 팀이 따로 만든 packoon-layer-studio (스튜디오 편집기). 장면 코드(`src/studio-fragment.html`)를 `js/title/title-scene.js`로, 그림 `assets/*.png` 12장을 `assets/title/`로 그대로 옮겼다. 편집기 패널·슬라이더·저장 상태 복원만 뺐다.
- 설정은 스튜디오의 `scene-defaults.json` 값 그대로다 (`assets/title/scene-defaults.json`, 코드용 사본은 `js/title/scene-data.js`). 전체 입체감 15%, 안개 43 px/s, 팩쿤 반응 0.25, 숲길 반응 0.2, 까치 숨김.
- **자동 재생 없음**: 움직임 중 눈의 불편함 보고가 있어, 열 때마다 정지 상태다. 움직임 켜기를 직접 눌러야만 움직인다. 기기의 "동작 줄이기"가 켜져 있으면 알리고, 움직이는 중에 켜지면 멈춘다. 이것으로 불편함이 해결됐다고 보지는 않는다.
- 이미지 보간(`imageSmoothingQuality=high`)과 흐림 캐시는 원본 그대로다. 정지 화면은 스튜디오와 픽셀 단위로 같다 (1280×720, 시간 0, 마우스 가운데에서 비교).
- 첫 화면을 닫으면 프레임 루프·ResizeObserver·마우스 이벤트를 정리하고 큰 그림도 메모리에서 놓는다.
- 그림 12장이 원본 PNG라 합쳐 약 16MB다. 처음 열 때 불러오는 동안 "가을 숲을 불러오고 있습니다"가 뜨고, 그동안에도 메뉴는 누를 수 있다.
- 스튜디오에서 설정을 바꾸면 `scene-defaults.json`을 `assets/title/`에 다시 복사하고 `js/title/scene-data.js`의 같은 값을 맞춘다. 그림을 바꾸면 `assets/title/`의 PNG를 바꾼다.

## 표(CSV)와 게임 데이터

아이템(이름·레어도·설명), 보스 부위(이름·내구도·부수면 얻는 것·핵심), 달래기 진정수치, 가보 가공법, 아빠의 수첩 메모, 미니게임·채집 수치(`minigames.csv`), 조작감·시간 수치(`tuning.csv`)는 **`design/data/*.csv`가 유일한 원본**이다. 게임은 표에서 만든 `js/data/tables.js`를 읽는다 (더블클릭으로 열 때 브라우저가 CSV를 못 읽게 막아서, 표를 데이터 파일로 바꿔 둔다).

- 표(`minigames.csv`·`tuning.csv` 포함)를 고친 뒤: `node prototypes/web/tools/build-data.js` (레포 맨 위 폴더에서). 외부 패키지 없이 node만 있으면 된다.
- 맞는지만 보기: `node prototypes/web/tools/build-data.js --check` (표와 다르면 실패한다)
- 가공법·진정수치 칸의 물건 이름이 items.csv에 없거나 모양이 틀리면 변환기가 어느 줄인지 알려 주고 멈춘다. 미니게임·조작·시간 표도 필수 값 누락·빈 칸·숫자 오류·판정 범위를 검사한다.
- `tables.js`는 직접 고치지 않는다.
- 코드에 남는 것: 대사, 위치, 그림, 진행 순서, 공격 종류와 예고 글, NPC·지역 이름(대사에도 적혀 있어서), 먹으면 오르는 체력 같은 게임 전용 값. 수치 단위와 표 편집 방법은 `design/data/README.md`를 따른다.

## 새 버전을 올릴 때

`index.html`이 부르는 css·js 주소 끝에 `?v=20261030pa43arcs2` 같은 버전 표시가 붙어 있다. 파일을 고쳐 올릴 때마다 이 값을 **모두 같은 새 값**으로 바꾼다 (날짜 + 알파벳 하나면 충분하다). 안 바꾸면 GitHub Pages가 파일을 10분쯤 브라우저에 저장해 두는 탓에, 새 `index.html`과 옛 js가 섞여 검은 화면이 뜰 수 있다.

## 검증하려던 것 (단풍골)

- 물물교환만으로 지역 하나의 흐름이 돌아가는가 (교환 연쇄 2단계, 호감 축 3종)
- 타이밍 채집이 단순 줍기보다 재미있는가
- 부위 공략 전투(부위 공격 → 회피 → 빈틈 표식 타격 → 내구도 깎기)가 턴제보다 템포가 좋은가
- 필드(도트)와 전투(수묵화)의 스타일 전환이 효과적인가
- NPC 전투(꿀밤으로 연장을 뺏기고 피하기만)가 재미 요소가 되는가

## 검증하려던 것 (돌너머 마을, 제안)

- 같은 물건(칡꽃)이 지역에 따라 귀해지는 교환이 재미있는가
- 교환 연쇄 3단계(칡꽃 → 결명자 → 맷돌 깨어남 → 메밀가루 → 길)가 막히지 않고 이어지는가
- 가보를 직접 깨우고 그 가보로 약을 만드는 흐름이 단풍골(남이 약을 지어 줌)과 다르게 느껴지는가
- 졸음 깨우기, 돌 쌓기 같은 짧은 미니게임이 대화 사이에 잘 섞이는가
- 아빠의 소원 돌로 보스를 달래는 장면이 부수는 것보다 끌리는가

## 검증하려던 것 (큰 장터, 제안)

- 앞 지역의 가보(맷돌)가 다음 가보(시루)를 깨우는 흐름이 자연스러운가
- 낮과 밤을 숙소에서 바꾸는 것이 장터 분위기와 부엉 영감 성격을 잘 살리는가
- 아빠의 엿을 도깨비에게 줄지 고르는 선택이 마음에 남는가
- 엿가위 장단, 김 올리기 같은 리듬·조절 미니게임이 대화 사이에 잘 섞이는가

## 검증하려던 것 (북쪽 영산과 엔딩, 제안)

- 숨은 사연이 퍼즐이 아니라 장부 한 장과 산군의 이야기를 "받는" 장면으로 잘 전해지는가
- 마지막 교환(이름을 내놓기)과 새 이름 짓기가 물물교환 세계의 결말로 납득되는가
- 설피·지름길처럼 "속도가 아니라 접근"으로 길이 열리는 성장이 재미있는가
- 겨울에서 봄으로 바뀌는 전환이 보상으로 느껴지는가

## 지역 하나 더하기

1. `js/regions/<지역 id>/` 폴더를 만들고 단풍골 폴더를 본보기로 파일을 나눈다.
   - `region.js`: `defineRegion(id, {...})`로 지역 정보와 처음 상태, `defineIcons`(아이콘) / `defineGather`(채집)
   - `art.js`: NPC 도트 그림과 소품
   - `field.js`: 배경, 장애물, 날씨, 휘두르기·쓰러짐 처리
   - `enemies.js`: `defineEnemies`로 전투 상대와 수묵 그림
   - `story.js`: NPC 대화와 교환, 지금 할 일, 지역 전용 미니게임
2. `index.html`의 지역 `<script>` 목록 아래에 새 파일을 같은 모양으로 덧붙인다 (`game.js`보다 위).
3. 앞 지역의 `defineRegion`에 `next: '<새 지역 id>'`를 적는다.

가보는 `awaken('<가보 id>')`로 깨운다. 깨어난 가보는 `G.awake`에 남고, 가공법은 깨어난 뒤에만 쓰인다. 지역 전용 미니게임 창은 돌너머의 돌 쌓기처럼 지역 파일에서 만들어 `#shell`에 붙이고 `defineMinigame`으로 등록한다.

엔진 파일은 고치지 않아도 된다. 엔진에 없는 기능(새 공격, 새 미니게임)도 지역 파일에서 `defineAttacks` / `defineBullets` / `defineMinigame`으로 더할 수 있다. 여러 지역이 같이 쓸 것 같으면 그때 엔진으로 옮긴다.

### 구역·경치·길손·도장 쓰는 법

PA-43의 공통 엔진이다. 지역 파일에서 `Rg.zones`와 `Rg.startZone`을 선언하면 구역 방식으로 움직인다. 선언하지 않은 지역은 기존 한 구역 맵을 그대로 쓴다. 공용 상수 `CLASSIC`은 `?classic=1`일 때만 참이다. 옛 지역 정의는 남겨 두고 `if(!CLASSIC){ ... }` 안에서 확장 정의를 붙인다. 단풍골 `field.js`의 `// 예시` 블록과 `notebook.csv`의 예시 한 줄은 다음 단계에서 교체한다.

```js
if(!CLASSIC){
  Rg.startZone='village';
  Rg.zones={
    village:{w:2800,startX:70,ground:GROUND,platforms:[{x:300,y:160,w:60}],
      drawBack:drawVillage,weather:()=>Vfx.setWeather('maple'),
      npcs:['dodam'], // REG.npcs의 id. 또는 NPC 정의에 zone:'village'를 적는다.
      digs:[{id:'village_root',x:470,item:'root',done:false}],
      pickups:[{id:'village_acorn',x:210,y:GROUND,item:'acorn',got:false}],
      exits:{right:{to:'forest',need:()=>G.tool==='sickle',
        reason:'낫으로 덩굴을 걷어야 한다.',drawBlocked:drawVines}},
      doors:[{x:120,to:'forest',toX:160,label:'숲으로',draw:drawSign}],
      examines:[{id:'wheel',x:620,label:'물레방아 살펴보기',
        text:['물레방아가 멈춰 있다.','나무 틈으로 물소리가 난다.']}],
      wanderers:[{id:'visitor',name:'길손',x:900,draw:drawVisitor,
        talk:()=>talk([['길손','잠깐 쉬었다 갈까?',[
          {t:'함께 쉰다',go:()=>talk([['길손','이제 좀 낫네.']],()=>finishWanderer('visitor'))},
          {t:'먼저 갈게',go:null}]]]),greeting:'다음 길에서 또 보자.'}],
      stamps:[{id:'root_mark',x:330,y:160,note:'stamp:galchamgol:root_mark'}],
      vistas:[{id:'valley',x:700,from:0,to:400,sound:'wind',
        thought:'집이 저렇게 작아 보이네.',diary:'언덕에서 집 쪽을 돌아봤다.',
        layers:[{speed:.15,draw:drawFarHills},{speed:.5,draw:drawVillageRoofs}]}]},
    forest:{w:2600,startX:160,npcs:[],platforms:[],drawBack:drawForest,
      exits:{left:'village'},newState:()=>({enemies:[]}),
      step:()=>{ /* zoneState().enemies 중 이 구역의 적만 갱신 */ },
      drawActors:()=>{ /* 같은 상태를 그림 */ }}
  };
}
```

- 구역의 `w`는 화면 폭 400 이상이다. `ground`는 발이 닿는 바닥 y이며 기본은 192다. 발판·NPC·조사점은 구역 안 좌표다. NPC·길손·조사점의 `y`를 생략하면 바닥이다. `npcs`를 생략하면 NPC의 `zone`으로 거르고, NPC의 `zone`도 없으면 시작 구역에 둔다. `npcs:[]`는 아무 NPC도 두지 않는다.
- `drawBack`, `drawScenery`, `drawActors`, `drawFront`, `weather`, `weatherFront`, `ambient`, `step`, `onHit`, `onPickup`, `drawPickup`, `drawDig`, `maxX`, `faint`, `fieldBoss`는 현재 구역 것만 부른다. 구역 방식에서는 지역의 같은 이름 함수로 자동 대체하지 않는다. 필요한 공통 그림 함수는 각 구역에서 참조한다. `goal`, `onStart`, 교환·전투 결과 함수는 계속 지역에 둔다. 전투를 여는 조건도 해당 구역의 `step`에 둔다.
- 구역별 가변 상태는 `newState()`가 돌려주며 `zoneState()`로 읽는다. 이 함수는 순수한 초기값만 만든다. `G.digs`·`G.pickups`는 기존 저장 구조를 유지하고 `zone`으로 거른다. 구역에 선언한 채집·줍기 지점은 한 번만 복제한다. `id`는 구역 왕복과 저장 뒤에도 유지한다. 기존 `newState()`가 만든 지점이나 이후 코드에서 추가하는 지점은 `zone`이 없으면 시작 구역 소속이다. 다른 구역에 추가할 때는 `zone`도 적는다. 적의 상태·그림·갱신은 해당 구역에 함께 둔다.
- 가장자리 출구는 문자열 또는 `{to,need,reason,drawBlocked,toX,toY}`다. x가 16 미만 또는 `w-16` 초과가 되도록 밖으로 걸으면 전환하고, 기본 도착점은 반대쪽 가장자리다. 문은 E 또는 휴대폰 말걸기 버튼으로 연다. 문 도착점은 `toX`·`toY`, 없으면 대상 구역의 시작점이다. 조건은 통과 직전에 다시 검사한다. `need`는 소비 없는 판정 함수이며 `reason`은 막힌 이유다. `drawBlocked(x,y)`에는 화면 좌표를 준다. 가장자리 전환은 좌우 이동 입력을 유지하고 나머지 입력을 비운다. 문 전환은 입력을 모두 비운다.
- 조사·문·경치·길손·도장은 가까운 하나가 선택된다. 가로 차이는 기존 말 걸기 거리(현재 30px) 미만, 세로 차이는 `field_interact_y`(현재 24px) 미만이다. 경계와 같은 값은 제외한다. 조사 `text`는 문자열 또는 문자열 배열이며 한 번 열 때 한 칸씩 진행해 마지막에 머문다. 1~2줄은 문자열 안 줄바꿈으로 적는다.
- 길손은 `REG.wanderers`에 `{id,zone,x,draw,talk}`로 두어도 된다. 기존 `talk()`·선택지·교환 함수를 그대로 쓴다. **사연이나 교환이 끝난 콜백에서** `finishWanderer(id)`를 부른다. 거절·취소만으로 끝내지 않는다. 다시 말하면 `greeting`을 쓴다. 완료 id는 `G.f.wanderersDone`, 전체 수는 `G.f.wandererCount`에 저장된다. `wandererCount(regionId?)`로 지역별·전체 수를 읽는다. id는 한 지역 안에서 고유해야 한다.
- 도장은 기본적으로 E로 발견하고, `auto:true`이면 가까이 닿을 때 발견한다. 발견 전에는 `draw`를 호출하지 않아 숨긴다. 주변 단서는 지역 배경에 그린다. `note`는 `notebook.csv`의 `알게되는키`와 연결한다. 같은 형식의 행에 `종류=도장`, `쓴이=아빠`, `대상=쪽 제목`, `내용=그날 이야기`, `상태=제안`을 적고 데이터를 재생성한다. 기존 동물·물건 id를 바꾸지 않고 지역별 새 쪽id를 쓴다. 발견 때 `learn(note)`·반짝임·획득음은 한 번만 실행된다. 수첩의 도장 탭에서 읽는다. `stampCount(regionId?)`, `G.f.stampCount`, `G.f.stampsByRegion`으로 집계하며 `G.f.stampsFound`는 지역+id별 발견 기록이다. 열두 개 수집 뒤 엔딩 장면은 지역 콘텐츠 단계에서 연결한다.
- 경치는 HUD·패드·대화를 걷고 필드·채집·전투를 멈춘다. 처음에만 `thought`와 `diary`를 보인다. `from`·`to`는 카메라 x(px)이며 `0..w-400`으로 제한한다. `t=경과 프레임/vista_pan_frames`를 0~1로 제한하고 `from+(to-from)×(3t²-2t³)`으로 이동한다. 예: 0→400의 절반 시점은 200px다. 각 원경은 `cam=반올림(카메라 x×speed)`로 그리며 `draw(cam,t)`도 받는다. 멀수록 작은 `speed`를 쓴다. 그림 함수 배열도 허용하며 생략한 속도는 `(순번+1)/겹 수`다. R/M과 정수 좌표를 쓴다.
- 패닝은 현재 480프레임(8초) 뒤 멈춘다. 숨긴 탭에서는 경치 시간이 멈추고, 움직임 줄이기는 시작 위치의 정지 화면이다. 소리는 `wind` 또는 `water` 환경음 하나를 반복하며 돌아오면 정리한다. 다음 키·터치 한 번으로 돌아오고 그 입력은 필드에 전달하지 않는다. 경치·화면 전환 중에는 저장하지 않는다.
- 구역·위치·조사 횟수·길손·도장·첫 경치 기록은 기존 저장 키에 함께 남는다. 구역 정보 없는 옛 저장은 시작 구역에서 기존 위치와 진행을 이어받는다. 모르는 구역 id는 시작 구역의 시작점으로 돌린다. 구역을 선언하지 않은 지역과 `?classic=1`에서는 확장 상호작용을 쓰지 않는다. 새 `G.f` 칸이 없으면 아직 발견·완료하지 않은 상태로 읽는다.

수치 원본은 `tuning.csv`의 `field_interact_y`, `zone_transition_frames`, `vista_pan_frames`다. 판정은 60Hz 갱신 기준이며 전환은 현재 18프레임(0.3초), 움직임 줄이기에서는 즉시다. 구역마다 핸들러나 타이머를 등록하지 않고, 전환 때 Vfx 대기열과 필드 입자를 비운다.

### 기록·별명·집으로 보내기 API (PA-43 3단계)

개발자 결정의 상태는 [결정 목록](../../design/proposals/decisions-1030.md)을 따른다. N 수첩에는 젊은 아빠의 그림·메모·도장만 둔다. B 너구리의 책은 `diary`(일기), `clues`(단서), `observations`(관찰), `nicknames`(별명), `habits`(손버릇), `recipes`(숨은 가공법), `replies`(까치 답장), `mom`(엄마 쪽지), `ledger`(장부) 탭이다. 기존 기록 행 id·학습 키·저장 키는 유지한다.

- `grantNickname(id,text,by)`: 별명을 한 번 기록한다. `by`는 붙여 준 동물 이름이며 첫 획득은 `true`, 같은 id나 잘못된 값은 `false`다. `nickname(id)`는 별명 문자열, 없으면 빈 문자열을 돌려준다.
- `sendHomeGift(regionId,itemId)`: 현재 지역 가공품 1개를 보내고 `true`를 돌려준다. CSV의 지역과 가공법 결과를 확인하며 원재료·다른 지역 가공품은 보내지 않는다. `itemId=null`이면 그림을 보내며 물건은 소비하지 않는다. 중복 발송·수량 부족·진행에 필요한 수량 부족 등은 `false`다. 기존 `home:<지역id>` 학습 키를 유지한다. 보내지 않아도 진행 가능하다.
- `Rg.homeReply`: 보낸 지역이 답장 글을 제공한다. 문자열, 문자열 배열, `talk` 행 배열 또는 발송 기록을 받아 그 값을 돌려주는 함수를 쓴다. 다음 지역의 `inn`·`shelter` 구역은 도착하거나 대화가 끝난 뒤 첫 자유 필드 갱신에서 `deliverHomeReply()`를 호출한다. 그 밖에는 까치(`magpie`·`kkachi`·이름/id의 `까치`), `rest`·`homeReply` 표시가 있는 접점, `maru`·`shelter` NPC에게 E로 말 걸 때 확인한다. 답장은 한 번 보여 주며 책에 남긴다. 문을 누른 순간에는 열지 않고 입장한 뒤 확인한다. 답장 글이 아직 없으면 보류한다.
  다음 지역이 없는 영산의 발송 기록은 보관하지만 자동 답장 장면은 열리지 않는다. 귀향 때 답장을 보여 줄 시점은 지역 작업과 확인해야 한다.
- `grantMask('choraengi'|'gaksi')`, `grantTool('pickaxe')`: 첫 획득은 `true`, 중복·잘못된 id는 `false`다. 획득과 장착은 별개다. 탈은 보스 전투에서 0·1·2 키 또는 화면 버튼으로 바꾼다. 곡괭이는 돌·얼음 부위 타격에 자동으로 쓰이며 없어도 모두 깰 수 있다. 속도·범위·피해 조절값은 `tuning.csv`가 원본이다.
- `noteFade()`: 엄마 쪽지를 한 단계 흐리게 하고 단계를 돌려준다. 지역 이동 때 엔진이 자동 호출하므로 지역 코드에서 중복 호출하지 않는다. 마지막 엔딩에서 `noteRestore()`가 글을 또렷하게 한다. 글이 흐려져도 보상·진행 불이익은 없다.

새 상태는 `G.nicknames`와 기존 `G.f` 안에 저장한다. 값이 없는 옛 저장은 빈 별명·미발송 상태로 읽는다. 쪽지는 현재 지역에 맞는 흐림 단계로 복원한다. 가방 겉모습은 돌너머 도착, 부엉 영감 신표, 영산 아빠 장면의 기존 진행 표시로 판단하며 칸 수는 늘리지 않는다.

### 공통 구역 전환 API

`zoneTransition(kind,opts={})`는 같은 지역의 `opts.to` 구역으로 전환한다. `kind`는 `zoom`(풍경 속으로 확대), `flow`(도착 구역에서 자동 흐름), `climb`(세로 화면 넘김)이다. 시작하면 `true`, 대상 오류·진행 중 연속 호출은 `false`를 돌려준다. 기존 지역 코드의 전환은 이번 단계에서 교체하지 않는다. `climb`은 화면 전환을 맡으며 등반 지형과 규칙은 지역 코드가 정한다.

옵션은 `x/y`(도착 필드 좌표 px), `frames`(양의 정수, 기본 `TABLES.TUNING.zone_transition_frames`), `sound`(효과음), `reverse`(확대·세로 전환의 역방향), `focusX/Y`(확대 중심의 화면 좌표 px), `fromX/Y`(자동 흐름의 도착 구역 시작 좌표 px), `draw(t,kind)`(0~1 진행에 따른 지역 추가 그림), `onComplete()`(완료 후 한 번 실행)다. 별도 시간·난이도 조절값은 지역 코드에 하드코딩하지 않고 CSV 값을 전달한다. 숨긴 탭에서는 전환 시간이 멈추며 기기의 움직임 줄이기 설정에서는 즉시 완료한다.

### 지역 음악 간주

지역 이동은 현재 테마의 반복 끝까지 이어진 뒤 `music.json`의 `travelInterludes`에 지정한 가야금 독주 두 마디를 거쳐 다음 테마 도입부로 들어간다. 현재 지역 테마는 모두 C·D·E·G·A 음계여서 `road_interlude`를 공유한다. 다른 음계의 지역곡을 더하면 같은 표에 그 음계의 간주 id를 연결한다. 같은 지역의 구역 이동에는 간주를 넣지 않는다.

`GameMusic.player.travel(nextTrackId)`가 전환을 예약하며 `GameMusic.getState().travel`과 진단의 `travel-outro`·`travel-interlude`·`travel-intro`로 확인한다. 다음 지역의 시작 화면에서도 예약을 유지한다. 대화·전투 등 별도 장면 음악은 기존 우선순위를 따른다. 탭 숨김·음소거 중에는 멈추고 돌아오면 남은 순서를 이어 간다. 간주 악보를 고친 뒤 `node tools/audio/render.js --web-data`, 확인은 `node tools/audio/render.js --check`다.
