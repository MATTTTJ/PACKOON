# 너구리 보부상 웹 프로토타입

브라우저에서 바로 열리는 프로토타입. **실제 게임 코드가 아니라 기획 검증용**이다. 콘텐츠와 게임 루프는 이 웹 버전으로 정하고, 많은 부분이 정해지면 Godot 4로 옮긴다. 옮길 때는 동작과 수치만 참고하고 코드는 새로 짠다.

- 플레이: https://mattttj.github.io/PACKOON/ (이 폴더로 넘어온다)
- 내 컴퓨터에서: `index.html`을 더블클릭해 브라우저로 연다. 빌드나 서버가 필요 없다.
- 저장: 화면 위 "저장" 버튼이나 너구리의 책 아래 "저장하기". 플레이 중 30초마다, 다음 지역으로 넘어갈 때도 저절로 저장된다 (대화·전투·미니게임 중에는 저장하지 않음). 저장은 그 기기의 브라우저에만 남는다. 시작 화면의 "이어서 하기"로 다시 시작하고, 책 아래 "처음부터 하기"는 한 번 더 눌러야 저장을 지운다 (`js/engine/save.js`).
- 지역 고르기: 시작 화면 아래 **개발용 · 이 지역부터 시작** 버튼을 누른다. 또는 주소 뒤에 `?region=<지역 id>`를 붙이면 그 지역부터 시작한다 (예: `index.html?region=dolneomeo`). 앞 지역은 그 지역의 `finish`대로 마친 것으로 친다. 확인용 바로가기라서 앞 지역의 단서 내용은 비어 있다.

지금 들어 있는 지역: 1 갈참골 → 2 돌너머 마을 → 3 큰 장터 → 4 북쪽 영산(엔딩). 처음부터 엔딩까지 이어서 플레이할 수 있다. 한 지역이 끝나면 끝 화면의 버튼으로 다음 지역에 들어가고, 보따리·연장·책(일기·단서·장부)·아빠의 수첩·호감·깨어난 가보는 그대로 이어진다. 체력은 다시 찬다.

## 첫 화면 (타이틀 장면)

처음 들어오면 가을 숲 타이틀 장면이 뜬다. 메뉴는 **이어서 하기**(저장이 있을 때) · **새로 시작**(지금의 프롤로그 화면으로) · **움직임 켜기**다. 주소에 `?region=`이 있으면 건너뛴다.

- 원본은 팀이 따로 만든 packoon-layer-studio (스튜디오 편집기). 장면 코드(`src/studio-fragment.html`)를 `js/title/title-scene.js`로, 그림 `assets/*.png` 12장을 `assets/title/`로 그대로 옮겼다. 편집기 패널·슬라이더·저장 상태 복원만 뺐다.
- 설정은 스튜디오의 `scene-defaults.json` 값 그대로다 (`assets/title/scene-defaults.json`, 코드용 사본은 `js/title/scene-data.js`). 전체 입체감 15%, 안개 43 px/s, 팩쿤 반응 0.25, 숲길 반응 0.2, 까치 숨김.
- **자동 재생 없음**: 움직임 중 눈의 불편함 보고가 있어, 열 때마다 정지 상태다. 움직임 켜기를 직접 눌러야만 움직인다. 기기의 "동작 줄이기"가 켜져 있으면 알리고, 움직이는 중에 켜지면 멈춘다. 이것으로 불편함이 해결됐다고 보지는 않는다.
- 이미지 보간(`imageSmoothingQuality=high`)과 흐림 캐시는 원본 그대로다. 정지 화면은 스튜디오와 픽셀 단위로 같다 (1280×720, 시간 0, 마우스 가운데에서 비교).
- 첫 화면을 닫으면 프레임 루프·ResizeObserver·마우스 이벤트를 정리하고 큰 그림도 메모리에서 놓는다.
- 그림 12장이 원본 PNG라 합쳐 약 16MB다. 처음 열 때 불러오는 동안 "가을 숲을 불러오고 있습니다"가 뜨고, 그동안에도 메뉴는 누를 수 있다.
- 스튜디오에서 설정을 바꾸면 `scene-defaults.json`을 `assets/title/`에 다시 복사하고 `js/title/scene-data.js`의 같은 값을 맞춘다. 그림을 바꾸면 `assets/title/`의 PNG를 바꾼다.

## 새 버전을 올릴 때

`index.html`이 부르는 css·js 주소 끝에 `?v=20261029b` 같은 버전 표시가 붙어 있다. 파일을 고쳐 올릴 때마다 이 값을 **모두 같은 새 값**으로 바꾼다 (날짜 + 알파벳 하나면 충분하다). 안 바꾸면 GitHub Pages가 파일을 10분쯤 브라우저에 저장해 두는 탓에, 새 `index.html`과 옛 js가 섞여 검은 화면이 뜰 수 있다.

## 검증하려던 것 (갈참골)

- 물물교환만으로 지역 하나의 흐름이 돌아가는가 (교환 연쇄 2단계, 호감 축 3종)
- 타이밍 채집이 단순 줍기보다 재미있는가
- 부위 공략 전투(부위 공격 → 회피 → 빈틈 표식 타격 → 내구도 깎기)가 턴제보다 템포가 좋은가
- 필드(도트)와 전투(수묵화)의 스타일 전환이 효과적인가
- NPC 전투(꿀밤으로 연장을 뺏기고 피하기만)가 재미 요소가 되는가

## 검증하려던 것 (돌너머 마을, 제안)

- 같은 물건(칡꽃)이 지역에 따라 귀해지는 교환이 재미있는가
- 교환 연쇄 3단계(칡꽃 → 결명자 → 맷돌 깨어남 → 메밀가루 → 길)가 막히지 않고 이어지는가
- 가보를 직접 깨우고 그 가보로 약을 만드는 흐름이 갈참골(남이 약을 지어 줌)과 다르게 느껴지는가
- 졸음 깨우기, 돌 쌓기 같은 짧은 미니게임이 대화 사이에 잘 섞이는가
- 아빠의 소원 돌로 보스를 달래는 장면이 부수는 것보다 끌리는가

## 검증하려던 것 (큰 장터, 제안)

- 앞 지역의 가보(맷돌)가 다음 가보(시루)를 깨우는 흐름이 자연스러운가
- 낮과 밤을 숙소에서 바꾸는 것이 장터 분위기와 부엉 영감 성격을 잘 살리는가
- 아빠의 엿을 도깨비에게 줄지 고르는 선택이 마음에 남는가
- 엿가위 장단, 김 올리기 같은 리듬·조절 미니게임이 대화 사이에 잘 섞이는가

## 검증하려던 것 (북쪽 영산과 엔딩, 제안)

- 숨은 사연이 퍼즐이 아니라 장부 한 장과 산군의 이야기를 "받는" 장면으로 잘 전해지는가
- 마지막 교환(이름을 내놓기)과 새 이름 짓기가 물물교환 세계의 결말로 납득되는가
- 설피·지름길처럼 "속도가 아니라 접근"으로 길이 열리는 성장이 재미있는가
- 겨울에서 봄으로 바뀌는 전환이 보상으로 느껴지는가

## 테스트에서 나온 피드백 (반영 완료)

- "친다"가 어떤 키인지 몰라 보스를 못 깼다 → 표식 아래 [J] 표시, 흙더미 앞 "J · 캐기" 말풍선 추가
- 전투 속 복주머니 아이콘이 어색했다 → 연장을 쥔 너구리 손으로 교체
- 가공대 가운데 별도 복주머니가 불필요했다 → 고른 가보가 직접 가운데에 놓이도록 변경

## 파일 구조

```
index.html              화면 뼈대와 <script> 목록 (읽는 순서가 중요하다)
css/style.css           모든 스타일
js/engine/              모든 지역이 같이 쓰는 것
  core.js               화면 크기, 도우미, 등록소(define*), 게임 상태와 아이템·단서·장부 함수
  input.js              키보드·터치 입력, 미니게임 창 등록
  dialog.js             대화창, NPC 말 걸기, 대화 초상
  gather.js             흙더미 채집 타이밍 미니게임
  icons.js              16×16 아이콘 그리기
  field.js              주인공 이동·점프·휘두르기, 줍기, 카메라, 필드 그리는 순서
  hud.js                체력, 손에 든 연장, 지금 할 일
  bag.js                보따리와 가보 가공대
  book.js               너구리의 책 (일기, 아빠 단서, 물품 장부)
  notebook.js           아빠의 보부상 수첩 (동물·물건 쪽, 아빠 메모 + 내 기록, learn)
  battle-ink.js         수묵 붓 도구
  battle.js             부위 공략 전투
  battle-attacks.js     부위 공격 목록 (sweep, spike, seed, slam, ember, shout)
  game.js               시작·끝 화면, 게임 루프, 부팅 (맨 마지막에 읽는다)
js/data/common.js       지역과 상관없는 것: 주먹밥, 연장, 가보 네 개
js/regions/<지역 id>/   지역 하나의 데이터와 전용 코드
```

일반 `<script>`를 차례로 읽는 방식이라 `file://`로 열어도 돈다(ES 모듈은 `file://`에서 막힌다). 엔진 파일의 맨 위 이름은 파일끼리 공유된다. 지역 파일은 `(()=>{ ... })()` 안에 넣고 `define*` 함수로만 내보내서, 지역끼리 이름이 부딪히지 않게 한다.

id는 `design/data/*.csv`와 같다. 지역 id는 `regions.csv`, 아이템은 `items.csv`, NPC는 `npcs.csv`, 전투 상대는 `bosses.csv`, 부위는 `boss_parts.csv`의 id를 쓴다.

## 지역 하나 더하기

1. `js/regions/<지역 id>/` 폴더를 만들고 갈참골 폴더를 본보기로 파일을 나눈다.
   - `notes.js`: `defineNotes(id, [...])`로 아빠의 수첩 쪽 (design/data/notebook.csv 와 같은 내용)
   - `region.js`: `defineRegion(id, {...})`로 지역 정보와 처음 상태, `defineItems` / `defineIcons` / `defineGather`, 깨어나는 가보의 `defineRecipes`
   - `art.js`: NPC 도트 그림과 소품
   - `field.js`: 배경, 장애물, 날씨, 휘두르기·쓰러짐 처리
   - `enemies.js`: `defineEnemies`로 전투 상대와 수묵 그림
   - `story.js`: NPC 대화와 교환, 지금 할 일, 지역 전용 미니게임
2. `index.html`의 지역 `<script>` 목록 아래에 새 파일을 같은 모양으로 덧붙인다 (`game.js`보다 위).
3. 앞 지역의 `defineRegion`에 `next: '<새 지역 id>'`를 적는다.

가보는 `awaken('<가보 id>')`로 깨운다. 깨어난 가보는 `G.awake`에 남고, 가공법(`defineRecipes`)은 깨어난 뒤에만 쓰인다. 지역 전용 미니게임 창은 돌너머의 돌 쌓기처럼 지역 파일에서 만들어 `#shell`에 붙이고 `defineMinigame`으로 등록한다.

엔진 파일은 고치지 않아도 된다. 엔진에 없는 기능(새 공격, 새 미니게임)도 지역 파일에서 `defineAttacks` / `defineBullets` / `defineMinigame`으로 더할 수 있다. 여러 지역이 같이 쓸 것 같으면 그때 엔진으로 옮긴다.

### `defineRegion`에 채울 것

| 이름 | 뜻 |
|---|---|
| `order` | 지역 순서 (regions.csv의 순서). 주소에 지역이 없으면 가장 작은 것부터 |
| `next` | (선택) 다음 지역 id. 있으면 끝 화면에 다음 지역 버튼이 나온다 |
| `finish(g)` | (선택) 뒤 지역부터 바로 시작할 때 이 지역을 마친 상태로 만드는 함수 |
| `name` | 화면에 나오는 지역 이름 |
| `world`, `startX` | 필드 가로 길이, 주인공 시작 위치 |
| `platforms` | 올라설 수 있는 통나무 `[{x, y, w}]` |
| `clueTotal` | 이 지역의 아빠 단서 개수. 책과 끝 화면은 지나온 지역을 모두 더해 센다 (`clueTotalSoFar()`) |
| `cover` | 상단 꼬리표(`tag`)·부제(`sub`), 시작 전 할 일 글(`ready`), 앞 지역 끝 화면의 버튼 글(`go`), 시작 화면(`title`), 끝 화면(`end`) 글 |
| `newState()` | 처음 상태: `inv`(보따리에 더해짐), `pickups`(줍는 것 `{x, y, item}`), `digs`(흙더미 `{x, item}`), `f`(진행 표시, 앞 지역 것과 합쳐지니 이름이 겹치지 않게), `rel`(NPC id별 호감 축, 이미 만난 NPC는 앞 값을 이어 씀), 그 밖에 지역 전용 상태(새 지역 것으로 바뀜) |
| `onStart()`, `endStats()` | 시작할 때 할 일, 끝 화면의 숫자 `[[이름, 값]]` |
| `npcs` | `[{id, name, x, talk(), draw(x, y, 방향), props(npc)?}]` |
| `goal()` | 지금 할 일 글 |
| `maxX()` | 지금 갈 수 있는 오른쪽 끝 |
| `step()` | 매 프레임 지역 진행 (몹, 장애물, 전투 시작 조건 등) |
| `onHit(x1, x2, 피해, 방향)` | 휘두르기가 흙더미 말고 다른 것에 닿았을 때 |
| `faint()` | 체력이 다 떨어졌을 때 돌아갈 자리 |
| `drawBack()` | 하늘·배경·땅 |
| `drawPickup(a, x, 흔들림)` | 줍는 것 하나 그리기 |
| `onPickup(a)` | (선택) 무언가를 주웠을 때 |
| `drawDig(d, x)` | (선택) 채집 자리를 직접 그리고 `true`를 돌려준다 (없거나 `false`면 흙더미) |
| `drawScenery()`, `drawActors()`, `drawFront()`, `ambient()` | (선택) 큰 배경물, 장애물·몹, 맨 앞(날씨 등), 멈춘 동안에도 도는 날씨 움직임 |
| `fieldBoss()` | (선택) 필드 보스 체력 막대를 띄울 때 `{name, hp, max}` |
| `gatherDiary` | (선택) 처음 채집했을 때 일기 `[id, 글]` |

### 아직 없는 것

- 대장간 창(`#forge`)은 갈참골 무쇠 전용이다. 다른 지역에서 비슷한 타이밍 미니게임이 필요하면 채집(`gather.js`)처럼 엔진으로 일반화한다.
