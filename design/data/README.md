# 기획 데이터 표

엑셀로 열어 고치는 표 모음이다. 지역, NPC, 교환, 아이템, 가보, 보스 같은 **목록형 기획은 여기가 원본**이다. 기획 문서(`design/gdd/`)는 큰 방향과 이유를 적고, 구체적인 목록은 이 표들을 가리킨다.

## 파일

| 파일 | 한 줄이 뜻하는 것 |
|---|---|
| `regions.csv` | 지역 하나 (계절, 색, 랜드마크, 가보, 보스, 귀한 열매) |
| `npcs.csv` | NPC 한 명 (종족, 성격, 역할, 호감 축, 미니게임, 아빠 단서) |
| `trades.csv` | 교환 하나 (누가 무엇을 원하고 무엇을 주는지). 같은 NPC도 지역이 다르면 줄이 따로 있다 |
| `items.csv` | 아이템 하나 (레어도 단계, 종류, 얻는 곳, 도감 등록 여부). 도감 칸 `O` 는 아빠의 수첩에 물건 쪽이 있다는 뜻 |
| `notebook.csv` | 아빠의 보부상 수첩의 한 줄 (어느 쪽, 아빠가 처음부터 적어 둔 것인지 내가 알게 되어 적는 것인지, 언제 알게 되는지). 알게되는키는 웹 코드의 `learn()` 이름 |
| `heirlooms.csv` | 가보 하나 (깨어나는 지역, 깨우는 NPC, 가공법) |
| `bosses.csv` | 전투 하나 (보스, NPC 전투). 통과 조건과 달래기 |
| `boss_parts.csv` | 보스의 부위 하나 (내구도, 공격, 부수면 얻는 재료) |
| `minigames.csv` | 미니게임·채집의 수치 하나 (목표, 판정, 난이도, 대기, 호감 덤) |
| `tuning.csv` | 필드 조작·상호작용 거리·꾸벅이 졸음·자동 저장의 수치 하나 |

## 규칙

- **표를 고친 뒤에는 웹 게임 데이터를 다시 만든다**: 레포 맨 위 폴더에서 `node prototypes/web/tools/build-data.js`. 아이템·보스 부위·진정수치·가공법·수첩·미니게임·조작감·시간 수치는 웹 게임이 이 표에서 읽는다 (`prototypes/web/js/data/tables.js`).
- **가공법**(heirlooms.csv)과 **진정수치**(bosses.csv)는 `이름 숫자` 모양으로 적는다. 여럿이면 가운뎃점(`·`)으로 나눈다. 예: `쌀가루 2 + 팥 1 → 팥시루떡 1 · 메밀가루 2 → 메밀떡 1`, `싸리버섯 50 · 꾀꼬리버섯 50`. 이름은 items.csv의 이름과 같아야 한다. 진정수치는 선물 하나를 건넬 때 진정 게이지(100이 가득)가 오르는 양이다.

- **id는 영어 소문자이고 바꾸지 않는다.** 다른 표가 id로 서로를 가리킨다. 예: `npcs.csv`의 지역 칸 `dolneomeo`는 `regions.csv`의 `dolneomeo` 줄이다. 화면에 나오는 이름은 `이름` 칸에서 마음대로 바꿔도 된다.
- **상태 칸**은 기획 문서와 같은 세 가지만 쓴다.
  - `확정`: 정한 것
  - `제안`: 아직 확인이 필요한 것
  - `미정`: 열린 질문
- 칸 안에서 여러 개를 적을 때는 가운뎃점(`·`)으로 나눈다. 쉼표를 써도 되지만 엑셀이 알아서 따옴표를 붙인다.
- 레어도 단계는 1(가장 흔함)부터 5(전설)까지 숫자로 적는다. 단계 이름은 아직 미정이다. 웹 프로토타입은 임시로 흔함·보통·귀함·희귀·전설을 쓴다.
- items.csv의 `종류`는 `레어도단계` 바로 뒤에 적고, `재료`·`먹을거리`·`도구`·`귀한 것` 중 하나를 쓴다. 보따리에서 찾을 때를 기준으로 나누며, 종류 분류의 상태는 **제안**이다.
- items.csv의 `진행보호`는 `지역id:기존 G.f 완료표시:필요수량[:대체재묶음]`이다. 여러 용도는 `·`으로 나누고, 같은 지역·완료표시·묶음이면 대체재 중 하나만 필요하다. 묶음을 생략하면 각각 필요하다. `ended`는 해당 지역 종료를 뜻한다. 웹은 현재·이후 지역의 미완료 용도와 가공법을 읽어 선물 전후의 부족 수량을 비교한다. 완제품이 있으면 그 재료를 중복 확보하지 않으며, 가공 횟수는 필요량을 결과 수량으로 나눈 뒤 올림한다. 이 보호 방식은 제안이다.

## 미니게임과 조작·시간 수치

`minigames.csv`와 `tuning.csv`는 세로로 긴 표다. 한 줄은 `id`로 식별하는 값 하나이며, `미니게임` 또는 `분류`로 필터를 걸고 `값` 칸을 고친다. `값이름`은 읽기 쉬운 이름, `단위`와 `설명`은 적용 방법이다. 현재 웹에서 옮긴 값은 모두 **제안**이다. 꾸벅이의 졸음은 `tuning.csv`, 다른 미니게임과 아이템별 채집 판정은 `minigames.csv`에 있다.

웹은 초당 60번 규칙을 갱신한다. `프레임`은 이 갱신 한 번이며, `px`는 웹 필드 좌표 단위다. `%p`는 백분율의 차이, 판정 반폭은 기준 양쪽에 각각 허용하는 폭이다. 초·ms로 적힌 값은 실제 시간이다. Godot에서 새로 구현할 때도 단위와 비교 경계를 함께 참고한다. 낮밤은 시간 경과가 아니라 숙소에서 쉬는 행동으로 바뀌므로 주기 수치를 두지 않는다. 시간제한 없는 몸짓 읽기와 재도전 방식은 지역 시나리오를 따른다.

생성기는 필수 id 누락, 빈 칸, 숫자가 아닌 값, 중복 id, 잘못된 상태·부호·정수 단위와 어긋난 판정 범위를 검사한다. 몸짓·장단의 단계 수는 이미 구현된 선택지·노트 시각 목록 안에서만 줄일 수 있다. 새 단계나 값 종류를 추가하려면 웹 코드와 생성기의 필수 id 계약도 함께 고친다. 웹 출력은 `TABLES.MINIGAMES`와 `TABLES.TUNING`이며, 기본값을 코드에 따로 두지 않는다.

교환 재료·보상 수량은 `trades.csv`를 그대로 쓴다. 위치·색·그림 프레임, 전투 수치는 이번 표에 넣지 않았다. 대사와 지역 채집 설명에 쓰인 숫자는 자동으로 바뀌지 않으므로 기획 수치를 바꿀 때 문구도 함께 확인한다.

## 엑셀에서 저장할 때

**파일 > 다른 이름으로 저장 > `CSV UTF-8(쉼표로 분리)`**로 저장한다. 그냥 `CSV`로 저장하면 한글이 깨진다.
